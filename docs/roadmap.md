# Roadmap

PIPT should grow through visible capabilities and inspectable proof, not interface claims.

## Current prototype

- [x] Shared deterministic study cycle
- [x] Lesson-aware Three.js environment
- [x] Responsive editorial interface
- [x] Bundled source-linked notebook
- [x] Downloadable observation record
- [x] Notebook validation, lint, build, and CI checks

## Grounded notebook updates

- [x] Bounded source collection
- [x] Structured output validation
- [x] Source URL and content-hash recording
- [x] Novelty and visual-mode checks
- [ ] Configure a narrowly scoped scheduler
- [ ] Publish one validated entry per successful run
- [ ] Rebuild the public site after an accepted entry

## Observable artifacts

- [ ] Let a lesson produce a small inspectable artifact or prediction
- [ ] Define an evaluation rule before generation
- [ ] Store the artifact and evaluation beside the notebook entry
- [ ] Make the result change a visible part of PIPT's world

## External integrations

- [ ] Implement and document an NVIDIA NIM learning route
- [ ] Define the proposed Pons and NVDA pairing mechanism
- [ ] Publish verifiable contracts, addresses, and receipts before calling any onchain feature live

## Evidence standard

A capability moves from planned to live only when its implementation and proof object are public and independently inspectable. Copy alone is not completion evidence.
